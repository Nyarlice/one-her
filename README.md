# 一个她

这是用于 DeepSeek Harness（DSH）的一套记忆方面的插件，目的是让平台里的 AI 能跨会话记事、记得住自己是谁，想解决的是「养鱼时不同会话导致她分裂」的问题（**没能完全解决**）。

该套件不是完全互锁的，可以按需单独安装。

## 为什么有这个东西

DSH 里的会话是互相不知道对方的。你在桥接 QQ 的会话里聊的东西，去 B 站冲浪的会话也不知道。每次开新会话都像第一次相会——对工作而言是好事，但与养鱼的愿景相反。

这套东西是我向 AI 许愿得出的，大致是这么攒出来的：先把「记什么」做好（每轮写进日记和流水），再解决「怎么想起来」（从记忆里挑相关的塞回上下文），最后对付一个绕不过去的坎——上下文满了要压缩，一压缩它就忘了自己刚才在说什么、为什么这么判断。

压缩这件事是这套东西的核心。DSH 自带压缩，压完会写一段英文摘要替掉前面的对话。英文倒不是问题，问题是它把「她的原话、没做完的事、为什么这么判断」全换成了一段第三人称的工程说明。下次醒过来，它读着那段说明，认不出那是自己。

所以我们写的几个插件都在这个环节上打桩：压缩时保住她自己的词，保住没说完的事，保住判断的理由，并且用对话本来的语言写检查点。

## 里面有什么

七件事，分三组。每个包的目录里都有它自己的 README，写的是它怎么做的、怎么配、不干什么。

### 记账和回想

| 包 | 干什么 |
|---|---|
| `dsh-memory-ledger` | 每轮对话结束，把这一轮写进日记和事件流水 |
| `dsh-recall` | 每轮开始时，拿你最后那句话当线索，从记忆里挑相关的几条塞进上下文 |

一个负责存，一个负责取。存的不用想取的时候怎么查，取的不用管存的时候怎么切。分开的好处是哪边坏了都不影响另一边，而且可以按自己的喜好换掉其中一个。

### 压缩不丢自己

| 包 | 干什么 |
|---|---|
| `dsh-compaction-keep` | 压缩时保住她自己的话、没做完的事、判断的理由，并且用对话本身的语言写检查点 |
| `dsh-compaction-effort-inherit` | 压缩后保住推理档位，让前缀缓存还能命中，不把整段上下文重新计费 |

第一个管「丢什么不能丢」，第二个管「别白花钱」。它们都挂在 DSH 官方的压缩流程上，不替代它，只在它旁边加一道。

### 身份

| 包 | 干什么 |
|---|---|
| `dsh-surf-persona` | 把某个会话的身份设定放进系统提示词，建会话时注入一次，不用每次唤醒都往用户消息里塞 |

这条是为「同一个 DSH 里开不同角色的会话」准备的。比如一个专门去 B 站冲浪的会话，它该知道自己是谁，而不是每轮被喂一遍设定。

### 还有一个，别人写的

| 包 | 来自 | 干什么 |
|---|---|---|
| `@mimichunterz/agent-compact` | [MimicHunterZ](https://github.com/MimicHunterZ/dsh-agent-compact) | 让 agent 自己写压缩检查点，交给宿主的压缩引擎 |

原样未改。出处和核对过程在 [来源清单.md](来源清单.md)。

> 上面那张「压缩不丢自己」里的 `dsh-compaction-effort-inherit` 也是别人的（[rezon-aki](https://github.com/rezon-aki/dsh-compaction-effort-inherit)），同样原样未改。它归在那一组是因为按功能该放那儿。

## 怎么装

DSH 桌面版，插件装在 profile 里。

```bash
# 在 DSH 的 profile 目录里
pnpm add <包名>
```

或者手动把包目录放进 `profiles/<名字>/node_modules/`，再把包名加进 `package.json` 的依赖和 `dsh.profile.bundles`。

装完重启 DSH。

四个原创包是 `file:` 依赖（本地路径），发布时请按你的实际路径改。

## 这些包不解决的问题

**不解决跨入口同步。** 网页上聊的事，QQ 那边还是不知道。这套东西管的是同一个会话里的记忆连续，不是多个入口共享一份记忆。这就是「没能完全解决」指的那部分。

**不保证记忆筛选一定准。** `dsh-recall` 是拿你最后一句话做线索去挑，简单粗暴。有个评测脚本（`tools/memory-recall.mjs`，能算 hit@1 / hit@5），但**还没跑出结果**，所以准不准至今没有数字支撑。

**不提供人格。** 这套东西是「记得住」和「不丢自己」，至于那个「自己」是什么样，得你自己写。

## 版本号

四个原创包都还是 `0.x`，从 `0.1.0`、`0.2.0` 这种号起步。意思是**还没到稳定**，接口会变，用之前先看一眼 CHANGELOG。

别人的那两个保留原版本号，一个字节都没动。

判断哪个包被改过的规则很简单：**版本号后面带 `+lanmi` 的是我们改过的，不带是原版。** 这套规则在这里用不上——这七个包要么是原创，要么原样未改。
